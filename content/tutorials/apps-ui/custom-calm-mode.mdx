Calm Mode is CarLauncher's answer to a screen that's asking for too much
attention: a minimal ambient dashboard — clock, date, temperature — that
swaps in over whatever's running. It has no `car-lib` API, no automatic
trigger, and — for one of its two entry points — no permission string at
all.

<FileTree>
packages/apps/Car/Launcher/app/src/com/android/car/carlauncher/calmmode/
├── CalmModeActivity.java
└── CalmModeFragment.java       # the real work: fields, fade, dismiss
</FileTree>

## Step 1 — See what it actually renders

```bash
adb shell am start -n com.android.car.carlauncher/.calmmode.CalmModeActivity
adb shell uiautomator dump && grep -o 'text="[^"]*"' window_dump.xml
# text="Fri, Sep 11"
# text="77°"
# text="02:38"
```

A genuine ambient dashboard, not a placeholder. Each field is independently
config-gated:

```xml title="Relevant config booleans, all default true"
config_calmMode_showClock
config_calmMode_showDate
config_calmMode_showTemperature
config_calmMode_showMedia
config_calmMode_showNavigation
```

## Step 2 — Dismiss behaviour, and why it matters for theming

```java title="CalmModeFragment.java"
mContainerView.setOnClickListener(v -> getActivity().finish());
```

<Gotcha title="finish() reveals, it doesn't relaunch home">
A tap anywhere calls `finish()`, which pops Calm Mode off the task stack and
reveals whatever activity was already running underneath — not a fixed
"return to home" behaviour. If you're customising what happens after Calm
Mode, don't assume the launcher's home screen is what reappears.
</Gotcha>

## Step 3 — Choose which fields show, with an overlay

```xml title="An RRO overlaying CarLauncher's calm-mode config"
<resources>
    <bool name="config_calmMode_showMedia">false</bool>
    <bool name="config_calmMode_showNavigation">false</bool>
</resources>
```

Package it the same way as any other CarLauncher RRO — see the RRO tutorial
for the target-package and `<overlayable>` mechanics.

## Step 4 — Add your own Quick Controls entry point

The second entry point isn't gated by a permission at all:

```xml title="packages/apps/Car/Launcher/app/res/values/arrays.xml"
<string-array name="launcher_qc_provider_package_allowlist" translatable="false">
    <item>com.android.systemui</item>
</string-array>
```

<Gotcha title="Package identity, not a permission string">
`BaseQCProvider.enforceCallingPermissions()` checks the calling package's
literal name against this hardcoded allowlist — not an Android
`<uses-permission>` string at all. Adding your own Quick Controls tile that
launches Calm Mode (or anything else CarLauncher-internal) means adding your
package name here, not requesting a permission.
</Gotcha>

```xml title="Overlay adding your own package"
<string-array name="launcher_qc_provider_package_allowlist" translatable="false">
    <item>com.android.systemui</item>
    <item>com.example.vegaquickcontrols</item>
</string-array>
```

<Verify title="Verify Calm Mode still launches with your changes">
```bash
adb shell am start -n com.android.car.carlauncher/.calmmode.CalmModeActivity
adb shell uiautomator dump && grep -o 'text="[^"]*"' window_dump.xml
```
Confirm the fields you turned off no longer appear, and the ones left on
still render real data.
</Verify>

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| A config-gated field never shows even with its bool `true` | That field also depends on live state — e.g. an active navigation session or playing media — not the config flag alone |
| Your Quick Controls tile doesn't appear | Your package isn't in `launcher_qc_provider_package_allowlist` — a permission alone won't grant access here |
| Dismissing Calm Mode doesn't return to your expected screen | `finish()` reveals whatever was already running, not a fixed home destination |
